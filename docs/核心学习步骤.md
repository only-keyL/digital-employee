# 核心学习步骤

本文面向：有 5 年 Java 后端经验、Python 初学、正在转型 Agent / RAG 应用开发的同学。

学习原则：

1. 不从页面和零散 CRUD 开始，先抓主链路。
2. 不追求一次看懂所有代码，先知道每层负责什么。
3. 用 Java 后端思维类比：Router ≈ Controller，Service ≈ Application Service，Repository ≈ DAO / Mapper，LangGraph ≈ 工作流 / 状态机，RAG ≈ 搜索引擎 + 业务过滤 + LLM 生成。
4. 当前项目是 MVP，重点学习设计思想和可运行闭环，不学习生产化部署细节。

## 1. 当前项目的学习目标

学完当前项目，应该能掌握下面几件事：

1. 业务闭环：企业微信 / Web 提问 → 知识库检索 → 命中回答 → 未命中沉淀 → 人工审核知识卡片 → 同步向量库 → 反哺问答。
2. Python Web 主链路：FastAPI Router → Service → Repository → SQLAlchemy Session。
3. Agent 编排思想：把一次问答拆成多个节点，用 LangGraph 管理状态和分支。
4. RAG 基础实现：知识卡片转文本 → Embedding → Qdrant 向量检索 → MySQL 回查 → 命中判断。
5. LangChain 用法：PromptService 组织 prompt，LLMFactory 选择 MockLLM / DeepSeek，DeepSeekClient 用 `ChatOpenAI` 调模型。
6. LangSmith 思路：不是业务必需功能，而是给 LangGraph 调用加 trace，默认关闭，失败不影响问答。
7. MVP 边界：知道哪些是 Demo / Mock，哪些是生产前必须补齐。

## 4. LangGraph 工作流学习路径

LangGraph 是本项目 Agent 思想的核心。它把一次问答拆成可观测、可分支、可扩展的节点。

主流程：

```text
validate_input
-> preprocess_question
-> retrieve
-> match_judge
-> generate_answer / handle_miss / error_fallback
-> write_log
```

重点文件和函数：

| 文件 | 重点函数 |
|------|----------|
| `app/agent/workflow.py` | `build_ask_workflow`, `route_after_validate`, `route_after_retrieve`, `route_after_match`, `get_compiled_ask_graph` |
| `app/agent/nodes.py` | 全部节点函数，但按主链路阅读 |
| `app/agent/ask_state.py` | `AskState` 字段含义 |
| `app/agent/graph_runner.py` | `AskGraphRunner.run` |
| `app/agent/constants.py` | `ROUTE_*`, `FALLBACK_ANSWER`, `RETRIEVAL_ERROR_ANSWER` |

建议阅读顺序：

1. 先看 `workflow.py::build_ask_workflow`，画出节点图。
2. 再看 `workflow.py::route_after_*`，理解条件分支。
3. 再看 `ask_state.py::AskState`，理解 state 里有哪些字段。
4. 最后看 `nodes.py`，逐个节点理解输入、输出和下游。

每个节点重点：

| 节点函数 | 重点理解 |
|----------|----------|
| `validate_input_node` | 空问题直接结束，不写日志 |
| `preprocess_question_node` | 当前脱敏/改写是占位，等于原文 |
| `retrieve_node` | 调用 `RetrievalService.retrieve`，记录原始检索结果 |
| `match_judge_node` | 把检索结果转成 `matched/sources/similarity_score` |
| `generate_answer_node` | 命中后才调用 `AnswerGenerationService.generate` |
| `handle_miss_node` | 未命中不调用 LLM，返回固定话术 |
| `error_fallback_node` | 检索异常时返回系统兜底 |
| `write_log_node` | 调用 `AskLogService.write_log` 落库 |

阶段完成后要能回答：

1. 为什么 LangGraph 比一个大函数更适合做 Agent 编排？
2. `StateGraph(AskState)` 里的 State 是什么？
3. `add_edge` 和 `add_conditional_edges` 有什么区别？
4. 为什么 `compiled graph` 可以缓存，但数据库 Session 不能缓存？
5. 命中、未命中、检索异常分别走哪条分支？

## 5. RAG 检索学习路径

RAG 在本项目里不是一句“调用向量库”这么简单，它包含四步：

```text
用户问题
-> Embedding
-> Qdrant 向量检索
-> MySQL 回查业务状态
-> 阈值判断命中
```

重点文件和函数：

| 文件 | 重点函数 / 类 |
|------|---------------|
| `app/services/retrieval_service.py` | `RetrievalService.retrieve`, `_validate_hits`, `RetrievalResult`, `RetrievalHit` |
| `app/rag/qdrant_store.py` | `QdrantStore.search`, `QdrantSearchHit` |
| `app/rag/embedding_service.py` | `EmbeddingService.embed_text`, `_create_provider`, `FastEmbedProvider`, `MockEmbeddingProvider` |
| `app/repositories/knowledge_repository.py` | `get_searchable_by_id`, `list_approved_enabled` |
| `app/config/settings.py` | `top_k`, `similarity_threshold`, embedding / qdrant 配置字段 |

学习重点：

1. `QdrantStore.search()` 只负责向量相似度检索。
2. `RetrievalService._validate_hits()` 会回查 MySQL，过滤掉未审核、停用、删除的卡片。
3. `similarity_threshold` 决定相似度低于多少算未命中。
4. `top_k` 决定从向量库取多少候选。
5. RAG 的“可信”来自知识库，不来自 LLM 自己编。

阶段完成后要能回答：

1. 为什么 Qdrant 返回结果后还要查 MySQL？
2. `matched` 是谁决定的？LLM 能不能决定？
3. `similarity_score` 的业务意义是什么？
4. 检索异常和检索未命中有什么区别？
5. 如果知识卡片停用，为什么不应该继续被检索到？

## 6. 知识卡片入库到向量库学习路径

知识卡片进入向量库不是创建时自动完成，而是受状态控制。

核心规则：

```text
deleted=0
audit_status=approved
enabled=1
```

只有满足这三个条件，才应该进入 Qdrant。

重点文件和函数：

| 文件 | 重点函数 |
|------|----------|
| `app/routers/knowledge_router.py` | `create_knowledge_card`, `audit_knowledge_card`, `sync_knowledge_card_vector`, `enable_knowledge_card`, `disable_knowledge_card`, `delete_knowledge_card` |
| `app/services/knowledge_service.py` | `create`, `update`, `submit_audit`, `audit`, `enable`, `disable`, `soft_delete`, `sync_vector`, `_apply_vector_sync`, `_build_draft_card` |
| `app/services/vector_sync_service.py` | `should_index_card`, `sync_card`, `_sync_card_record`, `delete_card_vector`, `rebuild_all` |
| `app/services/knowledge_content.py` | `build_knowledge_content_text`, `compute_content_hash`, `card_to_content_dict` |
| `app/rag/qdrant_store.py` | `upsert_knowledge_card`, `delete_knowledge_card`, `rebuild_from_mysql`, `init_collection` |
| `scripts/rebuild_qdrant.py` | `main` |

学习路径：

1. 先看 `KnowledgeService.create`：新建知识卡片默认 `draft`，`vector_status=pending`。
2. 再看 `KnowledgeService.submit_audit`：草稿提交审核。
3. 再看 `KnowledgeService.audit`：审核通过 / 拒绝；审核后调用 `_apply_vector_sync`。
4. 再看 `VectorSyncService.should_index_card`：判断是否该进入 Qdrant。
5. 再看 `QdrantStore.upsert_knowledge_card`：拼文本、向量化、写 Qdrant。
6. 最后看 `scripts/rebuild_qdrant.py::main`：全量重建向量库。

阶段完成后要能回答：

1. 新建知识卡片为什么不直接进向量库？
2. `draft -> pending -> approved/rejected` 分别代表什么？
3. `VectorSyncService.should_index_card` 的三个条件是什么？
4. `content_hash` 用来解决什么问题？
5. 为什么停用/删除卡片时要删除 Qdrant 里的向量？
6. `rebuild_qdrant.py --recreate` 和单卡同步有什么区别？

## 8. LangSmith Trace 学习路径

LangSmith 在本项目里是“观测层”，不是业务主流程必需项。

调用关系：

```text
AskGraphRunner.run()
-> TraceService.is_enabled()
-> TraceService.invoke_graph()
-> _invoke_with_tracing()
-> graph.invoke(... callbacks=[tracer])
-> persist_trace_id()
```

重点文件和函数：

| 文件 | 重点函数 |
|------|----------|
| `app/agent/graph_runner.py` | `AskGraphRunner.run` |
| `app/observability/trace_service.py` | `is_enabled`, `invoke_graph`, `_invoke_with_tracing`, `_langchain_compat_env`, `extract_trace_id`, `persist_trace_id` |
| `app/observability/redaction.py` | `build_safe_metadata` |
| `app/repositories/question_repository.py` | `update_langsmith_trace_id` |
| `app/config/settings.py` | `is_langsmith_enabled` 和 `LANGSMITH_*` 配置 |

学习重点：

1. LangSmith 默认关闭。
2. 开启后，TraceService 包装 `graph.invoke`。
3. 上报 metadata 要注意隐私，不能上传问题全文、答案全文、知识正文。
4. LangSmith 异常时自动降级普通 `graph.invoke`，不影响 `/api/ask`。
5. `trace_id` 只写入 `question_log.langsmith_trace_id`，不返回给前端。

阶段完成后要能回答：

1. LangSmith 在系统里解决什么问题？
2. 为什么 tracing 失败不能影响正常问答？
3. `hide_inputs` / `hide_outputs` 为什么重要？
4. `trace_id` 存在哪里？为什么不返回给用户？
5. 什么信息适合放进 metadata，什么信息不适合？

## 12. 面试官最可能追问的 20 个问题

1. 你这个项目里的 Agent 到底体现在哪里？
2. 为什么使用 LangGraph，而不是一个普通 Service 方法顺序调用？
3. `AskState` 的设计有什么好处？
4. 命中知识库和未命中知识库分别怎么处理？
5. 未命中时为什么不直接让 LLM 回答？
6. RAG 检索链路是什么？
7. 为什么 Qdrant 返回后还要回查 MySQL？
8. 如何保证被删除、停用、未审核的知识不会被回答？
9. 知识卡片如何进入向量库？
10. 编辑知识卡片后，如何保证向量库更新？
11. Qdrant local 模式有什么 MVP 边界？
12. DeepSeek 是怎么通过 LangChain 接入的？
13. MockLLM 的作用是什么？
14. LLM 调用失败如何降级？
15. Prompt 中如何约束答案来源？
16. LangSmith 在这个项目里怎么接入？
17. 为什么 LangSmith 失败不能影响主流程？
18. 企业微信入口和 `/api/ask` 如何复用同一套问答链路？
19. 如何做企业微信消息去重？
20. 如果要生产上线，你会优先补哪些能力？

建议回答方向：

1. Agent 不是“多个智能体聊天”，而是“状态驱动的问答工作流”：校验、预处理、检索、判断、生成、兜底、落库。
2. LangGraph 让流程显式化，便于扩展、观测和分支治理。
3. RAG 的可信度来自已审核知识卡片，不来自 LLM 自由发挥。
4. 未命中沉淀闭环是业务价值核心。
