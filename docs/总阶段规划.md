# 总阶段规划

## 项目背景

当前项目已经完成企业微信数字员工助手生产 V1 增强版能力，具备知识卡片、RAG 问答、可信回答、来源引用、反馈闭环、运营看板、多轮追问和轻量记忆等功能。

现在新增一个轻量增强需求：

> 让系统支持上传公司已有的大段需求文档、操作文档、实施文档，并基于这些文档进行后续问答。

本次优化不推翻现有知识卡片体系，而是在现有知识卡片 RAG 基础上新增"文档知识库 RAG"。

## 总体设计思路

本次采用：

```text
文档上传
  ↓
文档解析
  ↓
文档切片
  ↓
MySQL 保存文档与切片
  ↓
Qdrant 同步文档切片
  ↓
/api/ask 同时检索知识卡片和文档切片
  ↓
回答时带来源引用
```

知识来源分为两类：

| 知识来源 | 作用 | 优先级 |
| ---- | --------------------- | --- |
| 知识卡片 | 高频问题、标准答案、人工审核后的高质量知识 | 高 |
| 文档切片 | 需求文档、操作手册、实施说明、培训文档 | 中 |

原则：

1. 知识卡片负责精准回答。
2. 文档切片负责扩大知识覆盖面。
3. 用户提问时优先使用知识卡片，再补充文档切片。
4. 文档来源必须可追溯。
5. 不把整篇文档作为一个向量块，必须先切片。

## 阶段划分

本次优化分为 3 个阶段：

| 阶段 | 阶段名称 | 类型 | 核心目标 |
| --- | ----------- | ------ | --------------------------------- |
| 阶段1 | 文档上传解析与切片入库 | 开发阶段 | 文档上传、解析、切片、MySQL 入库 |
| 阶段2 | 文档向量同步与问答接入 | 开发阶段 | 文档 chunk 同步 Qdrant，并接入 `/api/ask` |
| 阶段3 | 文档知识库交付总结 | 文档总结阶段 | 补充交付文档、调用链、验收脚本和演示说明 |

## 阶段1：文档上传解析与切片入库

### 目标

新增"文档知识库管理"后台能力。

本阶段完成：

1. 文档上传；
2. 文档主信息入库；
3. 文档文本解析；
4. 文档切片；
5. 文档切片入库；
6. 文档列表页面；
7. 文档详情页面；
8. 切片查看页面；
9. 阶段验收脚本。

### 支持文件类型

| 类型 | 是否支持 | 说明 |
| ------- | ---- | ------------- |
| `.txt` | 支持 | 基础文本 |
| `.md` | 支持 | 按标题层级切片 |
| `.docx` | 支持 | 提取段落文本 |
| `.pdf` | 基础支持 | 只支持可复制文本型 PDF |

PDF 本阶段边界：

```text
支持：普通文字型 PDF（pypdf / pdfplumber 基础文本提取）
不支持：扫描件、OCR、图片识别、复杂表格还原、页眉页脚智能清理、图文混排精准解析
```

### 新增表

```text
document_source
document_chunk
```

### 阶段1不做

1. 不接入 `/api/ask`。
2. 不同步 Qdrant。
3. 不调用 LLM。
4. 不生成候选 QA。
5. 不改 LangGraph 主流程。
6. 不改企微回调。

### 阶段1完成标准

1. 文档可上传。
2. 文档可解析。
3. 文档可切片。
4. 文档和切片可写入 MySQL。
5. 后台页面可查看。
6. 验收脚本通过。
7. 不影响现有功能。

## 阶段2：文档向量同步与问答接入

### 目标

让文档切片进入 RAG 检索链路，使用户可以基于上传文档进行问答，并在回答中看到文档来源。

### 本阶段完成

1. 文档 chunk 向量文本构建。
2. 文档 chunk Qdrant payload 构建。
3. 文档 chunk 同步 Qdrant。
4. 支持单文档同步。
5. 支持全部文档重建索引。
6. 改造检索逻辑，使其支持知识卡片和文档切片两类来源。
7. `/api/ask` 回答中返回文档来源。
8. 保持原有知识卡片问答能力不回归。

### 检索策略

推荐策略：

```text
用户提问
  ↓
问题改写 / 上下文增强
  ↓
优先检索知识卡片
  ↓
补充检索文档切片
  ↓
合并 TopK 上下文
  ↓
知识卡片优先级高于文档切片
  ↓
LLM 生成回答
  ↓
返回答案与来源引用
```

### Qdrant payload 要求

文档 chunk payload 至少包含：

```text
source_type=document_chunk
doc_id
chunk_id
doc_name
doc_type
system_name
module_name
section_title
section_path
page_no
chunk_index
content_hash
```

知识卡片 payload 保持兼容：

```text
source_type=knowledge_card
knowledge_id
title
system_name
module_name
tags
version
content_hash
```

### 阶段2不做

1. 不做复杂 rerank。
2. 不做 OCR。
3. 不做 PDF 表格精准解析。
4. 不做 AI 自动生成候选 QA。
5. 不改企业微信真实回调。
6. 不破坏原有知识卡片检索。

### 阶段2完成标准

1. 文档 chunk 可同步 Qdrant。
2. `/api/ask` 可命中文档切片。
3. 回答中可以展示文档来源。
4. 原有知识卡片问答不回归。
5. 回归脚本通过。
6. 文档来源可追溯到文档名、章节、页码或 chunk。
