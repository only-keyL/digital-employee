# 演示脚本与讲解话术

## 1. 演示准备

- [ ] MySQL、Redis 已启动
- [ ] `uvicorn` 运行在 `http://127.0.0.1:8001`
- [ ] 已执行 fast 或 full 回归通过
- [ ] 准备 Postman/curl 或控制台页面
- [ ] 若开启后台鉴权，准备 Admin Token（勿在演示中念出真实值）

## 2. 演示顺序（建议 20～30 分钟）

1. 健康检查与基础设施
2. 普通问答（命中）
3. 低置信度未命中
4. 【沉淀】+ 模板 + 投稿
5. 后台审核通过
6. 审核后 RAG 命中
7. 重复投稿 / 高风险 / 幂等
8. 一键回归

## 3. 普通问答演示

```powershell
# POST /api/ask-v2 或 mock_wecom 普通问题
```

**话术**：「顾问在群里问一句常见问题，系统不是瞎编，而是先去向量库找相似知识，置信度够才让大模型组织答案。」

## 4. 低置信度未命中演示

问一个库里没有的问题。

**话术**：「置信度低的时候我们宁可说不确定，还会记入未命中列表，方便后面补知识。」

## 5. 【沉淀】指令演示

```json
{"message_id":"demo-1","user_id":"u1","content":"【沉淀】"}
```

**话术**：「沉淀就像打开一个记事本模式，后面的消息会按模板收知识。」

## 6. 缺字段卡片演示

提交只有标题/短答案的卡片。

**话术**：「字段不全会提示补全，避免垃圾知识进库。」

## 7. 完整卡片投稿演示

按模板提交完整结构化卡片。

**话术**：「投稿后会生成待审核知识，不会直接进向量库，必须人工把关。」

## 8. 后台审核通过演示

打开 `/admin/knowledge/pending` → 审核通过。

**话术**：「管理员点通过后，系统才创建向量同步任务，异步写入 Qdrant。」

## 9. 审核通过后 RAG 命中演示

用与刚审核知识相关的问题再问一次。

**话术**：「这就是闭环：沉淀 → 审核 → 入库 → 问答能检索到。」

## 10. 重复投稿演示

提交与库内高度相似的知识。

**话术**：「重复疑似会标出来，不会自动合并旧知识，避免误覆盖。」

## 11. 高风险投稿演示

含删库、drop table 等危险描述的内容。

**话术**：「高风险内容直接拦截，宁可漏收也不乱收。」

## 12. 幂等演示

相同 `message_id` 连续提交两次【沉淀】。

**话术**：「企微可能重推消息，我们用 message_id 幂等，重复只返回第一次结果。」

## 13. 一键回归演示

```powershell
python scripts/prod/run_all_regression_checks.py --env-file "docs/prod/.env" --fast
```

**话术**：「上线前一条命令跑完配置、审核、安全等检查，省得人工漏项。」

## 14. 讲解话术（给领导 1 分钟版）

「这个项目解决的是实施群知识散落的问题。员工可以像聊天一样提问，系统用 RAG 找知识再让大模型回答；遇到好东西发送【沉淀】按模板投稿，管理员审核后才进入向量库。我们做了幂等防重复、后台鉴权、操作审计和一键回归，方便测试环境交付。真实企微回调是下一步，当前用模拟入口已经把业务跑通了。」
