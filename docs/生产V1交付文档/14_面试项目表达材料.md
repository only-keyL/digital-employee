# 面试项目表达材料

## 1. 三十秒介绍

「我做了一个企业微信场景的数字员工助手：群里可以问问题，系统用 RAG 检索知识库再让 DeepSeek 回答；也可以发【沉淀】把经验收成结构化知识，管理员审核后才进向量库。技术上是 FastAPI + LangGraph + Qdrant + MySQL，还做了幂等、后台鉴权和操作审计。」

## 2. 一分钟介绍

在上面的基础上补充：

「项目分阶段交付，从配置护栏、AI 基础设施、RAG 问答、模拟企微沉淀、后台审核，到上线前的安全扫描和一键回归。低置信度不强答，pending 知识不直接同步向量库。真实企微回调预留了接口，当前用 mock 入口验证完整闭环。」

## 3. 三分钟介绍

再补充架构与亮点：

「架构是 Router → Service → Repository，LangGraph 编排问答和沉淀两条链路。AskGraphV2 负责 Embedding、Qdrant 检索、置信度判断和 LLM 生成；KnowledgeDepositGraph 负责解析、质检、重复和风险检查。审核通过后异步入队 vector_sync_task，worker 写 Qdrant，payload 只存摘要不脱敏全文。阶段 6 做了 message_id 幂等、Header Token 保护后台、admin_operation_log 审计，以及 10+ 个 prod 回归脚本。」

## 4. 项目技术亮点

- LangGraph 统一编排问答与沉淀，节点可观测
- RAG + 置信度分层，低置信度不强答
- 人工审核闸门 + 异步向量同步
- message_id 幂等适配企微重推
- prod 配置硬校验 + 一键回归
- LangSmith/Qdrant payload 脱敏设计

## 5. 为什么用 LangGraph

「问答和沉淀都是多步骤流程，有分支和状态。LangGraph 比在一个大函数里写 if/else 更清晰，也方便接 LangSmith 看每一步。」

## 6. 为什么用 Qdrant

「知识问答需要语义检索，Qdrant 支持向量相似度搜索，也能 remote 部署，和 MySQL 结构化存储分工明确。」

## 7. 为什么要低置信度不强答

「实施场景怕胡说八道。检索分数低就说明库里没依据，应该提示不确定并记录未命中，让人去补知识。」

## 8. 为什么 pending 不直接入向量库

「未经审核的知识可能有错、重复或高风险。先 pending，管理员过了再入队同步，保证向量库质量。」

## 9. 为什么要 message_id 幂等

「企微或网关可能重复投递同一条消息。用 source+message_id 做幂等，避免重复建卡、重复问答记录。」

## 10. 为什么要审计日志

「审核是谁通过的、改了什么状态，上线后要能追溯。审计表存脱敏前后快照，满足内控要求。」

## 11. 常见面试追问与回答

**Q：和直接调 ChatGPT 有什么区别？**  
A：我们先用企业自己的知识检索，再让模型基于上下文回答，并有人工审核的知识入库流程，不是纯聊天。

**Q：向量库和 MySQL 怎么分工？**  
A：MySQL 存完整结构化知识和审核状态；Qdrant 存向量用于语义检索，payload 只放摘要字段。

**Q：如果 LLM 挂了怎么办？**  
A：配置层有 mock 降级，基础设施检查会暴露故障；低置信度路径本来就不强依赖 LLM。

**Q：为什么还没接真实企微？**  
A：先把业务闭环和治理做扎实。回调涉及 AES 和公网部署，单独一个阶段做更稳。

**Q：后台鉴权安全吗？**  
A：当前是内网 Header Token，适合测试交付；生产建议换 SSO/RBAC，文档里写清楚了边界。

**Q：你怎么保证不上线带密钥的代码？**  
A：有安全扫描脚本、gitignore、prod 启动检查 Git 是否跟踪 docs/prod/.env。
