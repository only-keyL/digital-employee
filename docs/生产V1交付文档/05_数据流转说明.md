# 数据流转说明

## 1. 用户问题如何进入 RAG

1. 用户通过 `POST /api/mock/wecom/message` 或 `POST /api/ask-v2` 提交问题文本
2. `AskGraphV2Runner` 对问题做 Embedding
3. `RagRetrievalService` 在 Qdrant `{collection}_rag` 集合检索 Top-K
4. 根据 `confidence_level` 决定是否调用 DeepSeek 生成答案

## 2. 知识卡片如何进入 pending

1. 用户【沉淀】开启 Redis Session
2. 提交结构化知识卡片文本
3. `KnowledgeDepositGraph` 解析字段、质检、重复/风险检查
4. 通过后创建 `knowledge_card`：`audit_status=pending`，`enabled=0`
5. 同时写 `knowledge_contribution` 关联 `knowledge_card_id`

## 3. pending 如何审核 approved

1. 管理员在 `/admin/knowledge/pending` 或 API 查看 pending 列表
2. `POST .../approve` → `audit_status=approved`，`enabled=1`
3. 关联 `knowledge_contribution.status` 同步为 `approved`

## 4. approved 如何进入 vector_sync_task

1. `AdminReviewService.approve_knowledge` 调用 `Stage3VectorSyncService.enqueue_for_card`
2. 插入 `vector_sync_task`：`status=pending`，`action=upsert`
3. `knowledge_card.vector_status=pending`

## 5. worker 如何同步 Qdrant

1. `run_vector_sync_worker.py` 拉取 pending 任务
2. `build_vector_text(card)` 生成 embedding 输入（可含正文，用于向量）
3. Embedding → Qdrant upsert
4. 成功：`task.status=success`，`card.vector_status=synced`

## 6. Qdrant payload 保存哪些字段

见 `app/rag/vector_payload_builder.build_qdrant_payload`：

| 字段 | 说明 |
| --- | --- |
| knowledge_id | 知识 ID |
| title | 标题 |
| question_preview | 问题摘要（≤120 字） |
| system_name / module_name / tags | 分类 |
| version / content_hash / updated_at | 版本与哈希 |

**不保存完整答案正文。**

## 7. DeepSeek prompt 使用哪些上下文

AskGraphV2 将检索到的知识卡片字段（标题、问题、答案、步骤等）拼入 prompt 上下文，具体见 `ask_graph_v2` 节点实现；低置信度时不调用 LLM 强答。

## 8. LangSmith 上传哪些脱敏字段

配置 `LANGSMITH_HIDE_INPUTS=true`、`LANGSMITH_HIDE_OUTPUTS=true` 时，不上传完整问题/答案/知识正文，主要记录 metadata（耗时、置信度、run_id 等）。

## 9. contribution 与 knowledge_card 关联

- `knowledge_contribution.knowledge_card_id` 指向生成的卡片
- 投稿状态与卡片审核状态由 `AdminReviewService` 联动更新

## 10. message_process_log 如何实现幂等

- 键：`source + message_id`（唯一约束）
- 首次：`status=processing` → 业务成功 → `success` + 脱敏 `response_json`
- 重复 success：直接返回 `response_json` 摘要
- 同 id 不同 content：`duplicate_conflict`

## 11. admin_operation_log 如何记录审计

- 审核通过/拒绝、mark-reviewed 等操作前取 before 快照
- 业务变更后写 after 快照（仅关键字段）
- 与主业务同一 `session`，`repo.save()` 提交

## 明确约束

| 对象 | 约束 |
| --- | --- |
| Qdrant payload | 不保存完整答案正文 |
| LangSmith | 不上传完整知识正文 |
| message_process_log | 不保存完整 raw_payload |
| admin_operation_log | 不保存 Admin Token |
