# 项目交付总览

## 1. 项目背景

企业微信实施群中，顾问与实施人员每天产生大量可复用经验，但分散在聊天记录中，难以检索与沉淀。本项目构建「数字员工助手」，支持：

- 群内/入口提问 → RAG 检索 + LLM 回答
- 指令式知识沉淀 → 结构化投稿 → 人工审核 → 向量入库
- 后台治理 → 投稿审核、重复/风险拦截、操作审计

## 2. 项目目标

| 目标 | 说明 |
| --- | --- |
| 可演示 | 本地/测试环境完整跑通问答与沉淀闭环 |
| 可验收 | 提供 prod 回归脚本与验收清单 |
| 可维护 | Repository → Service → Router 分层，中文注释 |
| 可扩展 | mock_wecom 与真实企微共用 WeComMessage 模型 |

## 3. 已完成能力

- 统一配置体系（dev/test/prod 校验）
- AI 基础设施健康检查（Redis、Qdrant、DeepSeek、LangSmith）
- RAG 问答（AskGraphV2，`/api/ask-v2`）
- 模拟企微统一入口（`/api/mock/wecom/message`）
- 指令式知识沉淀（【沉淀】→ 模板 → 投稿）
- 后台投稿/待审核知识审核
- 审核通过后向量同步任务 + worker
- message_id 幂等、后台 Token 鉴权、操作审计
- 安全扫描、一键回归、向量任务运维脚本

## 4. 未完成能力

- 真实企微回调、AES 解密、验签
- 正式服务器部署与 HTTPS
- 完整 SSO / RBAC
- 正式生产监控告警体系
- pending 知识自动同步 Qdrant（设计上必须人工审核后入队）

## 5. 当前技术栈

| 类别 | 技术 |
| --- | --- |
| Web | FastAPI、Jinja2、Bootstrap 5 |
| 数据库 | MySQL 8.x、SQLAlchemy |
| 向量 | Qdrant（local / remote） |
| 缓存 | Redis（沉淀 Session、企微去重 TTL 配置） |
| LLM | DeepSeek（可 Mock 降级） |
| Embedding | fastembed / 远程 API |
| 编排 | LangGraph（AskGraphV2、KnowledgeDepositGraph） |
| 观测 | LangSmith（脱敏 Trace） |

## 6. 当前核心模块

```text
app/core          配置、校验、鉴权、脱敏、启动检查
app/infra         Redis、Qdrant、LLM、Embedding、LangSmith 客户端
app/rag           检索、向量库、置信度
app/graphs        AskGraphV2、KnowledgeDepositGraph
app/services      业务服务（审核、幂等、向量同步等）
app/repositories  数据访问
app/routers       API 与页面路由
app/wecom         CommandRouter、指令检测、模拟消息
scripts/prod      生产/验收脚本
templates/admin   后台审核与审计页面
```

## 9. 当前风险

| 风险 | 说明 |
| --- | --- |
| Header Token 鉴权 | 仅适合内网管理，非正式 RBAC |
| processing 幂等 | 长时间 processing 需人工关注 |
| 安全扫描 | 正则扫描有误报/漏报可能 |
| 真实企微未接 | 生产群消息仍走 mock 入口 |
