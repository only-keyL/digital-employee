# 真实企微接入前置说明

## 1. 当前为什么还没接真实企微

- 阶段 4～6 优先完成**业务闭环**（mock 入口、沉淀、审核、幂等、审计）
- 真实回调涉及 AES 加解密、验签、公网 URL，风险高，不阻塞 MVP/二期核心验收
- `wecom_router` 已预留，`WECOM_ENABLED=false` 时不影响其他功能

## 2. mock_wecom 如何模拟真实企微

- 统一入口：`POST /api/mock/wecom/message`
- 请求体映射为 `WeComMessage`（message_id, user_id, content, group_id 等）
- `CommandRouter` 与真实企微目标链路一致
- `message_id` 幂等表可复用到真实 source=`wecom`

## 3. 真实企微接入需要准备什么

| 项 | 说明 |
| --- | --- |
| CorpID | 企业 ID |
| AgentID | 应用 AgentId |
| Secret | 应用 Secret |
| Token | 回调 Token |
| EncodingAESKey | 回调加解密 Key |
| 回调 URL | 公网可访问 HTTPS 地址 |

## 4. 内网穿透测试方案（阶段 B）

```mermaid
flowchart LR
    WeCom[企业微信服务器] --> Tunnel[内网穿透 ngrok/frp]
    Tunnel --> Local[本地 FastAPI :8001]
    Local --> WecomRouter[/api/wecom/callback]
```

- 本地启动 uvicorn
- 穿透工具映射 HTTPS 到本地
- 企微后台配置回调 URL
- 先验证 GET echostr，再验证 POST 消息

## 5. 服务器部署测试方案（阶段 C）

- 测试机部署 FastAPI + Nginx HTTPS
- 独立测试库与 test collection
- 执行 full 回归后再开真实回调

## 6. 企微回调 URL

默认路径：`/api/wecom/callback`（`WECOM_CALLBACK_PATH` 可配置）

## 7. Token / EncodingAESKey / CorpID / AgentID

均在 `.env` 配置，**禁止写入代码与文档真实值**。示例：

```text
WECOM_CORP_ID=your_corp_id
WECOM_AGENT_ID=your_agent_id
WECOM_SECRET=your_wecom_secret
WECOM_TOKEN=your_wecom_token
WECOM_ENCODING_AES_KEY=your_encoding_aes_key
```

## 8. AES 解密与验签

- 当前 `app/wecom/crypto.py` 为预留/部分实现
- 生产接入前必须完成：签名验证、AES 解密、XML 解析 → `WeComMessage`
- **本阶段未实现**，标注为后续工作

## 9. message_id 幂等如何复用

真实回调解析后：

```text
WeComMessage.source = "wecom"
WeComMessage.message_id = 企微 MsgId
  ↓
MessageIdempotencyService（与 mock 相同）
```

## 10. Redis session 如何复用

`DepositSessionService` 按 `source + group_id + user_id` 管理沉淀 Session，真实企微只需映射相同维度。

## 11. 真实企微接入风险

| 风险 | 说明 |
| --- | --- |
| 回调超时 | 需在 5s 内响应，重逻辑应异步 |
| 重复推送 | 必须依赖 message_id 幂等 |
| 密钥泄露 | Token/AES Key 仅 env 配置 |
| 多实例 | 幂等表在 MySQL，可跨实例；Redis Session 需共享 Redis |

## 12. 推荐接入步骤

### 阶段 A：继续使用 mock_wecom

完成业务培训、审核流程、RAG 效果验证。

### 阶段 B：内网穿透联调

配置回调 → 验签解密 → 映射 WeComMessage → 走 CommandRouter。

### 阶段 C：测试服务器线上回调

HTTPS + 独立测试环境 + full 回归 + 监控。
