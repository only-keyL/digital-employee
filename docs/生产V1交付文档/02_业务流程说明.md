# 业务流程说明

## 1. 普通问答流程

```mermaid
flowchart TD
    A[用户在模拟企微入口提问] --> B[WeComMessage 标准化]
    B --> C[CommandDetector 判断普通问题]
    C --> D[AskGraphV2]
    D --> E[Embedding 生成问题向量]
    E --> F[Qdrant 检索知识]
    F --> G{置信度是否足够}
    G -- 高/中 --> H[DeepSeek 基于知识上下文生成答案]
    G -- 低 --> I[返回低置信度提示并记录未命中]
    H --> J[写 ask_run / retrieval_log / llm_call_log]
    I --> J
    J --> K[LangSmith 脱敏 Trace]
    K --> L[返回用户]
```

**要点**：

- 入口：`POST /api/mock/wecom/message` 或 `POST /api/ask-v2`
- 低置信度不强答，写入 `unanswered_question`（AskGraphV2 路径）
- 原 MVP `/api/ask` 仍保留，未被替换

## 2. 知识沉淀流程

```mermaid
flowchart TD
    A[用户发送【沉淀】] --> B[Redis 创建沉淀 Session]
    B --> C[用户提交知识卡片]
    C --> D[KnowledgeDepositGraph]
    D --> E[解析结构化字段]
    E --> F{字段是否完整}
    F -- 否 --> G[提示补充字段]
    F -- 是 --> H[AI 质量检查]
    H --> I[MySQL / Qdrant 重复检查]
    I --> J[敏感信息和高风险检查]
    J --> K{是否通过}
    K -- 否 --> L[记录 contribution 并返回原因]
    K -- 是 --> M[生成 knowledge_card pending]
    M --> N[等待人工审核]
```

**要点**：

- 【沉淀】依赖 Redis Session（`DepositSessionService`）
- `pending` 知识**不会**直接写入 Qdrant
- 重复疑似、高风险会标记 `contribution` 状态，不自动合并/放行

## 3. 审核治理流程

```mermaid
flowchart TD
    A[管理员进入后台] --> B[查看投稿和待审核知识]
    B --> C{审核动作}
    C -- 通过 --> D[knowledge_card audit_status=approved]
    D --> E[enabled=1 vector_status=pending]
    E --> F[创建 vector_sync_task]
    F --> G[worker 同步 Qdrant]
    G --> H[vector_status=synced]
    C -- 拒绝 --> I[保存拒绝原因]
    I --> J[audit_status=rejected]
    J --> K[不创建向量任务]
```

**要点**：

- 审核通过由 `AdminReviewService.approve_knowledge` 入队 `vector_sync_task`
- worker：`python scripts/prod/run_vector_sync_worker.py`
- 审核/标记操作写入 `admin_operation_log`

## 4. 幂等流程

```mermaid
flowchart TD
    A[收到模拟企微消息] --> B[source + message_id]
    B --> C{是否处理过}
    C -- 未处理 --> D[创建 processing 记录]
    D --> E[执行业务]
    E --> F[保存 success 和脱敏响应]
    C -- 已成功 --> G[返回历史响应]
    C -- 内容冲突 --> H[返回 duplicate_conflict]
    C -- failed --> I[允许重试]
    C -- processing --> J[返回 duplicate_processing]
```

**要点**：

- 表：`message_process_log`
- 配置：`MESSAGE_DEDUP_ENABLED`、`MESSAGE_DEDUP_TTL_SECONDS`
- `processing` 超时自动恢复：本版本**未实现**，重复提交返回 `duplicate_processing`
