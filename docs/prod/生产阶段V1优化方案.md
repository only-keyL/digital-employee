# 一、生产 V1 最终目标

生产 V1 的定位：

```text
公司企业微信实施群可真实使用的知识沉淀型数字员工
```

生产 V1 必须具备：

```text
1. 企业微信真实回调可用。
2. 用户 @数字员工 后，普通问题进入智能问答链路。
3. 用户发送【沉淀】后，进入企微知识沉淀模式。
4. Qdrant 使用 remote/server 模式，不再使用 local 文件模式。
5. DeepSeek 或其他真实 LLM API 可用，不再生产环境使用 MockLLM。
6. LangGraph 问答图升级为带评分、风险判断、降级路径的生产工作流。
7. LangSmith 默认接入，可追踪一次问答/沉淀的完整链路。
8. Redis 支持企微消息去重和沉淀会话状态。
9. MySQL 记录问答日志、检索日志、模型日志、沉淀日志、审计日志。
10. 审核通过的知识才同步 Qdrant，避免污染知识库。
```

生产 V1 暂时不做：

```text
1. 多轮长期记忆。
2. 多 Agent 协作。
3. 自动审批入正式知识库。
4. 工单系统集成。
5. 大规模权限体系。
6. 前后端分离。
7. K8s 高可用部署。
```

原因很简单：你当前目标是 **小规模企业快速验证**，优先做“真实可用 + 可控 + 可追踪”，不要一开始把系统做成大型平台。

## 4. Qdrant 部署选择

你说准备采用 Qdrant remote。这里推荐优先 **自建 Qdrant Server**，不是 Qdrant Cloud。


Qdrant 官方支持 Docker 方式运行，文档示例是拉取 `qdrant/qdrant` 镜像，并暴露 6333/6334 端口，同时挂载存储目录。([Qdrant](https://qdrant.tech/documentation/quickstart/?utm_source=chatgpt.com))

你需要准备：

```text

3. 持久化磁盘目录。

```

环境变量建议：


# 八、阶段 3：向量同步任务化改造

## 目标

```text

  ↓

  ↓

  ↓

  ↓

```

## 验收标准

# 十一、阶段 6：AskGraphV2 问答图升级

## 目标

LangGraph 的核心就是 State、Nodes、Edges：State 是共享状态，Node 负责执行逻辑，Edge 决定下一个节点；条件边适合根据状态做分支。([LangChain 文档](https://docs.langchain.com/oss/python/langgraph/graph-api?utm_source=chatgpt.com))
所以生产版要把“命中/未命中”扩展为“评分、风险、决策”。

## AskGraphV2 流程

```text

  ↓

  ↓
classify_intent_node
  ↓

  ↓
retrieve_knowledge_node
  ↓
rerank_and_score_node
  ↓
route_by_retrieval_score
    ├── high_confidence → generate_answer_node
    ├── medium_confidence → generate_cautious_answer_node
    └── low_confidence → handle_miss_node
  ↓
answer_quality_score_node
  ↓
safety_check_node
  ↓
final_decision_node
    ├── direct_reply
    ├── reply_with_human_tip
    ├── transfer_to_human
    └── record_unanswered
  ↓
write_log_node
  ↓
build_response_node
  ↓
END
```

