# 多轮追问与轻量记忆说明

## 1. 为什么需要多轮追问

实施场景中常见连续短问：

```text
Q1：合同审批流找不到审批人怎么办？
Q2：那在哪里配置？
```

单轮 RAG 无法理解 Q2 的「那」指什么。阶段 6 用 **Redis 短期上下文 + 规则改写** 补全语义。

## 2. Redis Key 设计

```text
digital_employee:conversation:{group_id}:{user_id}
```

`group_id` 为空时：

```text
digital_employee:conversation:private:{user_id}
```

实现：`app/services/conversation_context_service.py` → `build_context_key`

## 3. TTL

**30 分钟（1800 秒）**，配置项 `conversation_context_ttl_seconds`。

## 4. 保存哪些上下文

最近 **1 轮** JSON 摘要：

- last_question、last_rewritten_question
- last_answer_summary（≤300 字）
- system_name、module_name
- primary_matched_card_id/title
- confidence_level、updated_at

## 5. 不保存什么

- 完整长答案原文
- 敏感配置、密钥
- 用户全部历史问题
- 长期个人画像

## 6. 追问识别规则

**明显追问关键词**：那、这个、刚才、在哪里、怎么配置、还是不行、然后呢 等。

**短句模糊**：长度 ≤ 20 且缺明确系统/模块，且含「怎么办/哪里/怎么/为什么/还是不行」。

实现：`ContextEnhanceService.is_follow_up_question`

## 7. 问题改写规则

### Redis 上下文改写

```text
在{system}的{module}场景下，针对「{last_question}」这个问题，继续追问：{current}
```

「还是不行」类：

```text
在{system}的{module}场景下，用户已按上一轮答案处理但仍未解决，继续排查：{last_question}
```

### 30 天轻量记忆

```text
结合用户近 30 天常问的{system} / {module}，查询：{current}
```

## 8. 30 天常问系统/模块

- 方法：`QuestionRepository.list_user_recent_modules(days=30, limit=3)`
- 仅查 `question_log`，不新增表
- 返回 system_name、module_name、ask_count
- **只在模糊问题、无 Redis 上下文时使用**

## 9. 明确问题优先级

```text
当前明确问题 > Redis 短期上下文 > 30 天轻量记忆
```

含「合同系统」「报销系统」「审批流」等 → 不改写。

## 10. Redis 失败降级策略

| 场景 | 行为 |
| --- | --- |
| Redis 读取失败 | 打 warning，返回 None，尝试 30 天记忆或单轮 |
| Redis 写入失败 | 打 warning，问答正常返回 |
| 未配置 REDIS_URL | 生产 Redis 客户端报错；验收用内存 Store |

**Redis 异常不中断主问答链路。**

## 11. question_log 字段

| 字段 | 含义 |
| --- | --- |
| question_raw | 原始问题 |
| rewritten_question | 改写后问题 |
| used_context | 1/0 |
| context_source | redis_recent_turn / user_recent_modules / none |

## 12. 接入点

- `/api/ask`：`AskService._build_initial_state` + `_save_conversation_context`
- 企微模拟：`CommandRouter._handle_normal_question`

## 13. 当前边界

- **规则改写**，非 LLM 改写
- 仅最近 1 轮 Redis，非复杂多轮 Agent
- 30 天记忆只做 system/module 统计，非全历史 prompt
