# 文档知识库 RAG 说明

## 1. 背景问题

企业实施项目中常见三类痛点：

| 痛点 | 说明 |
| --- | --- |
| 文档存量大 | 需求文档、操作手册、实施说明、培训材料分散在个人电脑或网盘 |
| 手工整理慢 | 把文档拆成「标准问答」需要专人逐条提炼，周期长 |
| 整篇检索不精准 | 若把整篇文档作为一个向量块，召回粒度粗、噪声大、来源难追溯 |

因此需要在**不推翻现有知识卡片体系**的前提下，让公司已有文档快速参与问答。

## 2. 设计结论

采用 **「知识卡片 + 文档切片」双知识源** 策略：

```text
前期：文档 RAG 扩大知识覆盖面（上传即切片、可检索）
中期：高频问题继续沉淀为知识卡片（人工审核、标准答案）
长期：双源并存，卡片优先、文档补充
```

**为什么这么设计？**

- 知识卡片经过审核，适合「标准答案」场景，命中时应优先展示。
- 文档切片覆盖广、沉淀快，适合「已有材料但没人整理 QA」的冷启动阶段。
- 切片粒度可控（约 500～1000 字 + 章节路径），比整篇文档向量更精准。

## 3. 两类知识源对比

| 维度 | 知识卡片 | 文档切片 |
| --- | --- | --- |
| 质量 | 高（人工审核） | 中（原始文档提取） |
| 覆盖 | 高频标准问题 | 大段需求/操作/实施文档 |
| 沉淀成本 | 高（需提炼 QA） | 低（上传即解析切片） |
| 检索优先级 | **高** | 中（补充上下文） |
| 来源追溯 | card_id / title | doc_name / section_path / page_no / chunk_id |
| 向量 payload | `source_type=knowledge_card` | `source_type=document_chunk` |

## 4. 当前实现能力

| 能力 | 状态 | 入口/说明 |
| --- | --- | --- |
| 文档上传 | 已实现 | `/documents/upload`、`POST /api/documents/upload` |
| 多格式解析 | 已实现 | `.txt` / `.md` / `.docx` / 文本型 `.pdf` |
| 文档切片 | 已实现 | 按标题/段落规则，带 `section_path` |
| MySQL 入库 | 已实现 | `document_source` + `document_chunk` |
| Qdrant 同步 | 已实现 | `POST /api/documents/{doc_id}/sync-vector` |
| `/api/ask` 检索 | 已实现 | 与知识卡片共用 collection，按 `source_type` 分流 |
| 来源引用 | 已实现 | `sources` 扩展字段 + 可信回答展示 |

## 5. 当前支持文件类型

| 类型 | 支持范围 |
| --- | --- |
| `.txt` | 按空行、段落切片 |
| `.md` | 按 `#` / `##` / `###` 标题层级切片 |
| `.docx` | 段落提取，尽量识别标题样式 |
| `.pdf` | **仅可复制文本型 PDF**；扫描件不支持 |

## 6. 当前边界

| # | 边界 | 说明 |
| --- | --- | --- |
| 1 | 扫描件 OCR | 未实现；PDF 无文本时 `parse_status=failed` |
| 2 | 复杂表格 | 仅基础文本提取，不保证结构 |
| 3 | 复杂 rerank | 单次 Qdrant 检索 + 规则合并，无多路 rerank |
| 4 | AI 自动候选 QA | 未从文档自动生成知识卡片 |
| 5 | 远程 Qdrant | 未配置时远程同步 warning，本地 `QdrantStore` 仍可用 |
| 6 | 文档权限 | 无细粒度 RBAC |
| 7 | 知识卡片优先 | 文档切片**不会**覆盖高质量知识卡片答案 |

## 7. answer_source 口径

`/api/ask` 与 `question_log` 中 `answer_source` 常见取值：

| 值 | 含义 |
| --- | --- |
| `knowledge_card` | 主要依据知识卡片命中 |
| `document_chunk` | 主要依据文档切片命中（无高质量卡片时） |
| `mixed` | 同时命中卡片与文档，卡片优先展示 |
| `qdrant_rag` | 通用 RAG 命中（多为知识卡片路径） |
| `unanswered` / `system_fallback` / `llm_fallback` | 未命中或降级 |
