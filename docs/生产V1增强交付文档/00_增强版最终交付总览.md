# 生产 V1 增强版最终交付总览

## 1. 项目背景

企业微信实施群每天产生大量重复问题：审批流配置、权限开通、系统报错排查等。传统做法是人工翻文档、找老同事，效率低且知识难以沉淀。

本项目 **企业微信数字员工实施助手（digital-employee-assistant）** 目标是把「问答 → 沉淀 → 反馈 → 治理 → 运营 → 追问」串成闭环，让数字员工可持续进化。

## 2. 原生产 V1 能力（二期基线）

在 MVP 之上，生产 V1 已具备：

- FastAPI + Jinja2 后台管理
- AskGraphV2 RAG 问答（Qdrant + LLM）
- 模拟企微指令式知识沉淀
- 后台审核、向量同步、安全幂等
- LangSmith 可观测

**当前边界**：真实企微回调尚未接入，演示以 `/api/mock/wecom/message` 为主。

## 3. 增强阶段 1～6 做了什么

| 阶段 | 名称 | 核心产出 |
| --- | --- | --- |
| 1 | 数据与日志体系增强 | `question_log` / `feedback_log` / `knowledge_card` 字段扩展；修订建议表、重复检测日志表 |
| 2 | 可信回答 + 置信度 + 来源 | `TrustedAnswerService`；高/中/低置信度展示策略；来源卡片写入日志 |
| 3 | 知识卡片重复检测 | `DuplicateCheckService`；企微沉淀路径重复预警；检测日志 |
| 4 | 反馈闭环 MVP | 有用/无用/补充反馈；质量计数；`knowledge_card_revision` 修订建议 |
| 5 | 运营看板 | `/operation-dashboard`；summary/tops API；16 项运营指标 |
| 6 | 多轮追问 + 30 天轻量记忆 | Redis 短期上下文；规则改写；`used_context` / `context_source` 落库 |

## 4. 当前系统最终能力

```text
可信回答 → 知识重复检测 → 反馈闭环 → 运营看板 → 多轮追问 → 文档化交付
```

**一句话**：这不是简单 RAG Demo，而是具备可信回答、知识治理、反馈进化、运营分析和上下文追问能力的企业知识数字员工。

## 5. 业务价值

- 实施同学提问即得答案，低置信度不强答，减少误导
- 未命中问题可沉淀为知识卡片，形成组织记忆
- 用户反馈驱动知识质量迭代
- 运营看板让管理者看见命中率、风险卡片、未命中 Top
- 多轮追问让「那在哪里配置？」类短问可用

## 6. 技术价值

- Repository → Service → Router 清晰分层
- LangGraph 编排问答与沉淀两条链路
- Qdrant 向量检索 + MySQL 结构化治理
- Redis 短期会话 + question_log 轻量统计
- 分阶段验收脚本保障回归

## 7. 比赛展示亮点

1. **可信回答**：带来源、有置信度、低分不强答
2. **知识治理**：重复检测预警 + 后台审核
3. **反馈进化**：补充不直接改库，生成 revision 建议
4. **可运营**：看板 16 项指标 + Top 列表
5. **可追问**：Redis 30 分钟上下文 + 30 天常问模块

## 8. 当前边界

- 真实企微回调未接入（模拟入口为主）
- 反馈 revision 未做审核流、未自动转正
- 多轮追问为规则改写，非 LLM 改写
- 看板无缓存，大数据量需后续优化
