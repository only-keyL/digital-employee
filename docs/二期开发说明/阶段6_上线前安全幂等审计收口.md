# 阶段6：上线前安全、幂等、审计与运维收口

## 1. 本阶段目标

在阶段 2～5 能力不回归的前提下，补齐上线前收口能力：

- mock_wecom `message_id` 幂等（`message_process_log`）
- 后台 `/api/admin/*`、`/admin/*` 轻量 Token 鉴权
- 审核操作审计（`admin_operation_log`）
- 安全扫描、一键回归、向量任务运维脚本
- 生产启动前自检增强

本文件为轻量说明，完整生产部署文档在阶段 7。

## 2. message_id 幂等设计

- 幂等键：`source + message_id`（唯一约束）
- 首次处理写入 `status=processing`，成功后 `success` 并保存脱敏 `response_json`
- 重复 success：直接返回历史响应，响应体带 `idempotent=true`
- 同 id 不同内容：`duplicate_conflict`，拒绝执行业务
- `status=failed` 允许重试（`retry_failed`）
- 由 `MESSAGE_DEDUP_ENABLED` 控制开关

## 3. 后台管理 Token 鉴权

- 配置项：`ADMIN_AUTH_ENABLED`、`ADMIN_TOKEN`、`ADMIN_TOKEN_HEADER`
- dev 默认关闭；prod 必须开启并配置强 Token
- API 通过请求头校验；HTML 页面支持 `admin_token` 查询参数（便于浏览器访问）
- 本阶段为内部保护，生产应接正式登录 / RBAC

## 4. 审核操作审计日志

- 表：`admin_operation_log`
- 覆盖：approve / reject / mark-reviewed / ignore_duplicate / keep_blocked
- before/after 仅保存关键字段摘要，不含完整正文与 Token
- 与审核主操作同一 DB 事务提交

## 5. 向量任务运维脚本

- `check_vector_tasks.py`：统计各状态数量、列出 failed 摘要、抽样不一致检查
- `retry_failed_vector_tasks.py`：将 failed 且未达 max_retries 的任务重置为 pending（支持 dry-run）

## 6. 安全扫描脚本

- `check_stage6_security.py`：检查 Git 跟踪、example 文件、代码库疑似密钥
- 跳过 `docs/prod` 目录内容扫描
- 命中高风险项时 exit 1（可配置 `SECURITY_SCAN_FAIL_ON_SECRET`）

## 7. 一键回归脚本

- `run_all_regression_checks.py`：顺序执行阶段 2～6 检查并输出中文汇总
- `--fast` 跳过 LLM/RAG 等耗时真实调用

## 8. 当前仍未做的事情

- 真实企业微信回调与 AES 加解密
- 完整登录系统 / RBAC
- Nginx / HTTPS / 服务器部署
- 完整生产运维手册（阶段 7）
- `status=processing` 超时自动解锁（本阶段仅记录，未实现复杂锁）

## 9. 真实企微接入前风险清单

| 风险 | 说明 | 建议 |
| --- | --- | --- |
| Token 鉴权非正式登录 | 仅 Header Token，易泄露或共享 | 接 SSO / RBAC |
| message_id 幂等依赖 DB | 与真实企微 msgid 规则需对齐 | 接入前联调 msgid 来源 |
| 审计日志 IP/UA 不完整 | 经代理时可能不准 | 生产配置可信 X-Forwarded-For |
| 安全扫描误报/漏报 | 正则扫描无法覆盖所有泄露 | 结合 pre-commit 与 CI |
| docs/prod/.env 本地存在 | 不得入 Git | 定期 `git ls-files` 检查 |
| pending 知识不同步 Qdrant | 审核通过后异步 task | 监控 vector_sync_task failed |
| LangSmith 脱敏 | 依赖配置开关 | prod 强制 hide inputs/outputs |
| Redis/Qdrant/LLM 外部依赖 | 异常需降级 | 已有日志与错误码，需告警 |
| 弱 Admin Token | prod 校验已拦截常见弱口令 | 使用足够长度随机 Token |
